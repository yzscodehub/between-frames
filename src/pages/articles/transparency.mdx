两张透明彩纸互换前后顺序，颜色通常会变。若两张纸互相穿过，就连“哪张在前”也要逐像素回答。先按物体中心排序能解决一部分场景，却不能给交叉区域找到一个全局正确顺序。

本篇沿着 **over 合成 → 对象排序 → 逐像素排序参考 → 加权混合近似** 展开。WBOIT 的目标是在有限存储与不逐片元排序的条件下获得稳定近似，不保证复现所有有序透明结果。

<h2 id="over">01 / 先约定线性颜色与 alpha</h2>

使用线性、非预乘的表面颜色 C 和 alpha a，对不透明背景 B：

<Formula tex={'C_{out}=aC+(1-a)B'} />

把 A 放在 B 前面，与把 B 放在 A 前面一般不同。alpha 在这里表示合成不透明度，没有按 sRGB 解码；颜色在线性空间计算，最后编码显示。详见 [线性颜色基础](/foundations/color/#alpha)。本篇没有折射、吸收路径长度与 Fresnel 透射，不把彩色半透明片称作真实玻璃。

<h2 id="sorting">03 / 精确参考为什么不直接作为实现？</h2>

本实验知道所有三个平面的解析表达，因而可以逐像素求命中并排序。一般网格场景需要获取数量不定的透明片元；逐像素链表、深度剥离等方法会引入额外存储、同步或多遍成本。本篇不实现这些通用方案，而用已知几何提供清楚的正确性基线。

CPU 参考独立计算正交射线与平面的距离，再排序并合成；GPU 参考用平面深度表达与固定长度排序。它们共享几何定义，但不共享排序实现。恰好相交且深度完全相同时，按稳定 ID 决定次序，定量检查优先避开这些退化点与外轮廓。

<h2 id="weighted">04 / 累加颜色，保留背景透过率</h2>

WBOIT 不试图恢复完整深度顺序，而分别保存加权颜色与剩余透过率：

<Formula tex={'A_{rgb}=\\sum_i C_i a_i w_i,\\quad A_a=\\sum_i a_i w_i,\\quad T=\\prod_i(1-a_i)'} />

<Formula tex={'C_{out}=\\frac{A_{rgb}}{\\max(A_a,\\epsilon)}(1-T)+BT'} />

没有贡献时颜色平均按零处理。背景的剩余比例由乘积 T 保留；颜色则被一个加权平均概括。因此，交换提交顺序不应在实数运算下改变结果，但这并不能证明其颜色等于精确 over。浮点累积仍可能有微小顺序差。

算法依据 [McGuire 与 Bavoil 的 WBOIT 论文](https://jcgt.org/published/0002/02/09/)。本实验使用一个单独声明的教学权重 w=max(0.01,(1−z)^p)，z 是本场景归一化深度，p 可调。它强调前层颜色，没有复制论文完整工程权重，也不宣称对所有场景最优。

实现使用两个 RGBA16F 缓冲：颜色累积以 ONE / ONE 相加；透过率先清为 1，再用 ZERO / ONE_MINUS_SRC_ALPHA 相乘。为避免依赖逐附件独立混合，分别绘制两遍透明层，再合成到线性输出。没有把 CPU 求和或预先排序伪装成 GPU WBOIT。

<h2 id="validation">07 / 把正确性问题拆开</h2>

- alpha=0：三种方法都应返回背景，不能出现除零或非法颜色。
- 单层：加权平均中的权重抵消，应与 over 一致。
- 多层交叉：中心排序可能失败；逐像素参考与 CPU 应在非退化点一致。
- 顺序反转：WBOIT 在半精度容差内保持稳定；左图可以明显变化。
- alpha=1：明确展示 WBOIT 的颜色偏差，不为“好看”隐藏反例。

透明度参数、几何倾斜或权重改变后，旧检查读数立即失效。只有选点或改变已选点的条件才读取小缓冲；正常交互不做全屏同步读回。此处深度权重不是距离吸收模型，也没有与不透明深度缓冲集成、MSAA、折射或体积输运。
