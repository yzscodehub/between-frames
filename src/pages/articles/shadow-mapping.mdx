一个点出现在画面里，只能说明相机看得见它。直接光源是否照得到它，还需要从光源的方向重新判断。阴影贴图把这第二次观察保存成一张深度图，再让相机画面里的表面逐一查询。

本篇用三个任务建立这套判断：**从光源看 → 交换分辨率与覆盖 → 检查偏移的代价。** 每次只改变任务指定的条件。条纹、台阶和橙色区域都有各自的原因，不能靠一个“阴影质量”滑块统统解释。

<h2 id="visibility">01 / 直接阴影与 GTAO，问的是不同的问题</h2>

[GTAO](/articles/gtao/)估计表面周围一片方向上的局部环境可见性。这里则询问：从一个指定光源看向接收点，前面是否有遮挡物？物体与地面接触时，两者都可能出现暗部，但这不意味着它们可以互相替代。

实验先从光源位置光栅化全部网格，深度测试保留每个纹素最近的表面。再从相机得到当前可见表面的世界位置，将它投影回光图。**光源先看到别人，再看到接收点，接收点就被遮挡。**

场景着色包含独立的材质颜色和形状明暗。判断阴影数值时，请切到“可见度 · 1 亮 / 0 暗”；这个信号才直接对应后面的比较结果。背景和无法提供有效比较的橙色区域，不是可用于判断表面阴影的普通样本。

<h2 id="projection">02 / 世界位置、投影深度与轴向距离</h2>

把接收点的世界位置记为 p，光源的观察与投影矩阵记为 VL、PL。先做矩阵变换，再进行透视除法：

<Formula tex={'q=P_LV_L\\begin{bmatrix}p\\\\1\\end{bmatrix},\\qquad uv=\\tfrac12\\left(\\frac{q_{xy}}{q_w}+1\\right),\\qquad d_r=\\tfrac12\\left(\\frac{q_z}{q_w}+1\\right)'} />

WebGPU 迁移保留了旧分享状态对应的相机矩阵约定。顶点送入 WebGPU 光栅化前，将裁剪 z 转换为 `(z+w)/2`；下面的光图查询仍用原矩阵得到一致的 [0,1] 深度。不要把这段兼容转换误认为 WebGPU 的原生裁剪范围仍是 [−1,1]。

uv 决定查哪个位置，dr 是与光栅深度一致的 [0,1] 值。q 的 w 不为正、深度越过裁剪范围，或者 uv 不在光图内时，不能继续假装光源看到了完整信息。

本实验的光源相机固定在 **(−3.5, 7, 4.5)**，朝向世界原点。默认视角为 75°，近裁剪面 n=0.5，远裁剪面 f=25，光图为正方形。界面的“光源视角”改变光图覆盖，不把这个光源自动变成具有另一套发射规律的聚光灯。

还要区分光源轴向距离 z 与投影深度 d。z 是光源观察空间中沿前向轴的正距离，不是到光源的欧氏距离。当前普通透视投影满足：

<Formula tex={'d(z)=\\frac{f}{f-n}-\\frac{fn}{(f-n)z},\\qquad z(d)=\\frac{fn}{f-d(f-n)}'} />

距离加倍时，d 不会加倍。后续要计算平均遮挡距离和半影尺寸，必须先用右式恢复 z。光图清除值 d=1 反算为 f，只表示这个裁剪范围内没有记录到更近的表面，不证明远平面处真的有一堵墙。

<details>
<summary>展开：为什么比较深度之前必须做透视除法？</summary>

透视投影用齐次坐标保留与距离有关的缩放。q 的 x、y、z 都还不是纹理坐标或最终深度；除以 qw 后，点才进入标准化设备坐标，再映射到 [0,1]。少了这一步，不同距离的点会使用不一致的比较尺度。

这里 z 越大，d 越大，因此在相同约定下可以比较前后关系。但单调不等于线性：比较可以直接使用 d，几何长度运算却不能直接套在 d 上。

</details>

<h2 id="lab">03 / 实验一：从光源看</h2>

先点任务 **“1 · 从光源看”**。它载入“接触与悬空”场景，并显示光源深度图。图中的明暗表示线性轴距，观察方向来自光源，不是当前主相机。此时不能在光图上选择相机接收点；切回“场景着色”或“可见度”后，再点击地面。

<h2 id="coverage">04 / 实验二：一张图装进多少世界？</h2>

一张 N×N 的图只有有限数量的采样位置。在与光源像平面平行、轴距为 z 的截面上，单个纹素覆盖的宽度约为：

<Formula tex={'\\Delta x(z)=\\frac{2z\\tan(\\theta/2)}{N}'} />

θ 是光源视角。固定视角时，提高 N 会细分覆盖；固定 N 时，扩大视角会让同一个纹素容纳更多世界。斜面上的实际投影足迹还会被进一步拉长，不能只用这个截面宽度代表所有接收面。

<h3 id="mapping-task-two">实验 2 / 同一张图装进更多世界，边缘会怎样？</h3>
<dl>
<dt>问题</dt><dd>阴影覆盖范围与细柱轮廓精度之间有什么交换？</dd>
<dt>预测</dt><dd>保持覆盖，提高分辨率通常减少台阶；保持分辨率，扩大视角会降低局部采样密度。视角过窄则可能丢失覆盖。</dd>
<dt>操作</dt><dd>载入“2 · 分辨率与覆盖”，保持相机与视角，先把光图从 128 改到 512；然后固定 512，只改变“光源视角”。</dd>
<dt>证据</dt><dd>观察细柱阴影、斜面轮廓和光图范围；在场景视图重选接收点，查看实际纹素 UV 与比较状态。橙色表示光图窗口越界或接收平面修正无法提供有效比较，不能只归因于分辨率。</dd>
<dt>结论</dt><dd>分辨率只有连同覆盖范围才有意义；让光图看得更广，不会免费保留同样的局部精度。</dd>

<h2 id="bias">05 / 实验三：深度偏移为何既有用又有代价？</h2>

接收点投影到连续 uv，存储深度却来自一个离散纹素。斜面上，这两个位置的真实深度可能已经不同，再加上光栅化与浮点舍入，表面便可能误判为遮住了自己，产生条纹或斑点。

本实验把偏移 b 定义为**光源轴向的世界长度**。它先从接收轴距中减去 b，再投影成与光图相同的深度尺度：

<Formula tex={'V_{\\mathrm{hard}}=\\mathbf{1}\\!\\left[d(\\widetilde z_r-b)\\leq D(u_t,v_t)\\right]'} />

这里 D 是实际深度纹理；平面修正关闭时，z̃r 就是接收点轴距，开启时则是对应纹素中心的接收平面轴距。正偏移让接收点在比较中稍微靠近光源，减少自遮挡；偏移过大，也会把本来应遮挡的接近关系一起放过。

<section className="ray-task" aria-labelledby="mapping-task-three">
<h3 id="mapping-task-three">实验 3 / 消除条纹时，会不会把接触阴影推开？</h3>
<dl>
<dt>问题</dt><dd>深度偏移与接收平面修正，分别修正了什么？</dd>
<dt>预测</dt><dd>增大偏移可能减轻自遮挡，也可能让接触阴影脱离；按实际纹素中心修正斜面，可以减少一部分位置错配而少依赖固定偏移。</dd>
<dt>操作</dt><dd>载入“3 · 偏移的代价”，保持硬阴影。先从零缓慢增大“深度偏移”，观察斜面与柱脚；再恢复较小偏移，单独开启“接收平面修正”。</dd>
<dt>证据</dt><dd>比较条纹、接触处与样本的最终阈值。选择斜面内部和柱脚附近两个点分别核对，不把画面整体变亮当作修复证据。</dd>
<dt>结论</dt><dd>固定偏移改变深度判定余量，平面修正对齐比较位置；二者不是同一个参数，也没有统一适用的“越大越好”。</dd>
<dt>边界</dt><dd>局部平面不能代表曲率变化或另一侧几何，轮廓与近乎平行的情况仍需检查。这里也没有移动真实网格或光线起点。</dd>
</dl>
</section>

<h2 id="plane">06 / 为什么一定要用实际纹素中心？</h2>

设连续横坐标为 u，最近读取的纹素编号为 k。实际采样中心是 ut=(k+0.5)/N，而不是原来的 u。即使每个轴只差半个纹素，斜面上也会对应不同深度。这里先确定真正读取的纹素中心，再用从光源经过该中心的射线与接收平面相交。

<Formula tex={'k=\\operatorname{clamp}(\\lfloor Nu\\rfloor,0,N-1),\\qquad u_t=\\frac{k+\\tfrac12}{N}'} />

纹素编号公式只用于已经通过覆盖检查的 UV；越界时先返回无效，不把边界纹素当作缺失的几何。

它修正的是“光图在那个位置看到接收平面时，应该记录多深”。如果实际纹素看到的是更近的遮挡者，修正之后仍应判为遮挡；不能把所有深度差都抹平。

曲面掠射处，纹素射线可能无法与局部接收平面形成有效交点，或修正后的轴距落在 near/far 范围之外。这些情况也显示为橙色。保持其他参数不变，关闭“接收平面修正”，可以观察橙弧变化以及自遮挡重新出现的代价；不能把这种局部平面近似失效简单解释成光图分辨率不足。

<details>
<summary>展开：纹素射线与接收平面的相交推导</summary>

令 O 为光源位置，ν 为接收点 p 的几何法线，dt 为穿过实际纹素中心的世界空间单位方向。接收平面满足 ν·(x−p)=0。代入 x=O+tdt，可得：

<Formula tex={'t=\\frac{\\nu\\cdot(p-O)}{\\nu\\cdot d_t},\\qquad x_t=O+td_t,\\qquad \\widetilde z_r=-\\left(V_L\\begin{bmatrix}x_t\\\\1\\end{bmatrix}\\right)_z'} />

先得到世界交点，再变回光源空间求轴距；单位方向下的 t 是沿射线长度，不能直接拿它替代轴距。分母接近零、交点在光源后方或超出有效裁剪范围时，当前样本不能声称有完整覆盖。两个轴都要使用实际纹素中心，不能用连续 u 配离散 v。

</details>

<h2 id="evidence">07 / 两种 CPU 核对，验证不同环节</h2>

检查面板保留了两条证据链。**CPU 光图纹素射线**从光源通过同一个纹素中心，与生成网格的同一组世界三角形独立求交，再投影得到深度。这用于核对真实 DepthTexture 中存下的值。球体在本组实验中也是三角网格，CPU 不会偷偷换成解析球。

**同一 GPU 样本的 CPU 复算**则使用已经从 Shader 读回的深度和阈值，再做比较或平均。它能检查计算与展示是否一致，却不能独立证明输入深度正确。光栅覆盖边缘、共有边与浮点容差还需要结合确定性用例判断，不能要求所有边界都达到双精度机器误差。

另一个按钮可以为**选中点**生成 1024 样本的完整几何面积可见率。它与硬阴影的中心方向查询目标不同；二者的差不能全部归因于代码错误，也不是全图图像误差。下一篇将利用这个参考检查 PCSS 的面积阴影近似。

关于比较结果的过滤，可继续阅读 [GPU Gems 第 11 章](https://developer.nvidia.com/gpugems/gpugems/part-ii-lighting-and-shadows/chapter-11-shadow-map-antialiasing)。本篇的投影约定、偏移单位、场景和纹素检查都以本站实际实现为准。CSM、VSM、EVSM 与时间稳定化不在本次实验范围内。
