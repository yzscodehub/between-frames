方向光告诉材质“一束光从哪里来”。环境光照则把四周所有方向都作为潜在入射。转动环境，球面亮区也会移动；提高粗糙度，窄小亮区的响应会变宽。这不是给背光面加一个固定 ambient 常数，也不是直接把背景纹理投到球上。

本篇依次比较 **逐方向积分 → 预滤波方向图 → 分离 BRDF 的近似**。先把目标说清，再考虑如何复用计算。实验没有环境遮挡或间接遮蔽；完整环境可见是它的显式假设。

<h2 id="environment">01 / 环境图描述方向，不描述附近的位置</h2>

我们用一个程序化方向函数生成线性 RGB 入射辐射度：常量白环境、宽亮区环境、窄亮区反例。旋转角只改变环境相对表面的方向。它相当于无限远环境，因此所有表面点看到同一方向时取得相同值，没有位置视差。

本实验用正交相机观察单位球。白 Lambert 与 F₀=0.04 的单散射 GGX 分开显示，避免把材质混合方式也引入比较；它们都没有额外方向光、阴影或隐藏补光。下一步做完整材质时，还需要明确漫反射与镜面之间的能量分配。

<h2 id="integral">03 / 一个像素，要加上哪些方向？</h2>

<Formula tex={'L_o(n,v)=\\int_{\\Omega^+}L_i(l)f_r(n,l,v)(n\\cdot l)\\,d\\omega_l'} />

Lambert 白表面 f=1/π。在常量单位环境中，结果应为 1。GPU 用余弦加权方向采样，f × cos / pdf 抵消后，只需平均环境值。对镜面 GGX，本篇采用与 PBR 篇一致的 D、Smith G₁ 与 Schlick 定义，α=roughness²；半向量采样后将 PDF 转到反射方向，贡献包含 F G (v·h)/((n·v)(n·h))。

左图是每像素 256 样本的确定性低差异估计，**不是精确真值**。很窄的亮区会让有限方向采样漏掉贡献；增加屏幕分辨率也不等于增加每个表面的积分样本。粗糙度范围限制为 0.2–1，理想镜面不在本篇连续分布实验内。

<h2 id="prefilter">04 / 预滤波复用什么，也丢掉什么？</h2>

中图先在一组粗糙度层上生成环境方向图，再按反射方向与粗糙度查询。镜面预滤波固定 N=V=R，将采样环境值按 NoL 加权并归一化；真实像素另积分 BRDF 的两个系数 A、B，近似写作：

<Formula tex={'L_o\\approx L_{prefiltered}(R,r)\\,[F_0 A(NoV,r)+B(NoV,r)]'} />

将光照分布与 BRDF 响应拆开便于复用，但丢掉了两者的部分相关性，尤其不能假定掠射与窄亮区都能被一个预滤波方向完美代表。[Filament 的 IBL 说明](https://google.github.io/filament/main/filament.html#lighting/imagebasedlights)讨论了这类预积分与分离近似；本站保留自己的 Smith G₁ 乘积定义，没有照搬其所有材质近似。

工程实现使用七列 64×32 经纬图集：六列镜面粗糙度，最后一列 Lambert 积分。每列每像素 256 样本，层内双线性，粗糙度层间线性插值。这是便于观察的离散图集，不是完整 cubemap mip 链，也没有实现 Three.js PMREM。经纬接缝采用边界夹取，低分辨率与接缝会带来额外误差。

真实引擎通常会缓存 BRDF 查找表。本演示为了直接核对公式，在计算着色器中重新计算 A/B，因此中图不能用于宣称“比左图快多少”。图集只在环境或旋转改变时重建；粗糙度、信号与曝光变化会复用它。

<h2 id="reference">06 / 实验三：用独立积分拆分误差</h2>

选球面点后，GPU 通过存储缓冲异步读回三个方法的线性结果。独立 CPU 参考使用均匀立体角 Fibonacci 序列与另一种 Smith λ 表达，分别计算 32,768 与 65,536 样本；它不调用 GPU 半向量采样代码。两档差仅提供收敛线索，不是严格误差界。

<h2 id="limits">07 / 先诊断，再决定补什么</h2>

- 转动常量环境却变化：先检查方向约定、归一化和显示链路。
- 窄亮区出现跳变：区分积分采样、图集分辨率与经纬接缝。
- 掠射区偏差较大：检查分离假设与 BRDF 项，不只增加预滤波层数。
- 室内物体没有接触遮蔽：本模型假设整个环境可见；它不是全局光照，也没有局部探针视差修正。

镜面响应采用单散射模型，会遗漏多次微表面反射；本篇没有透射、各向异性或完整材质层。与 [PBR](/articles/pbr/#integral) 的积分边界保持一致；想看如何找到场景中的反射表面，可继续 [SSR](/articles/ssr/#input)。
